# Directive AI — модуль организаторов

Этот каталог находится в том же репозитории, что и редактор, но не входит в папку `starter/` и ученический архив. Он содержит подключаемый скрипт и шлюз. `AI_PROVIDER=mock` честно показывает демо-режим. Для облачной модели установите `AI_PROVIDER=cloud`, `AI_MODEL`, `AI_API_KEY` и совместимый `AI_BASE_URL` на сервере. Ключи не попадают в браузер. Ответ модели проверяется сервером и браузерным плагином.

```bash
cd directive-ai
npm run build
EVENT_CODE=long-random-code ALLOWED_ORIGINS=http://127.0.0.1:8080 npm start
npm test
```

Для показа раздайте скопированный ученический `starter/` отдельным HTTP-сервером на разрешённом origin. Наставник добавляет после `brushes.js` одну строку:

```html
<script src="https://artist.example.org/artist/v1/artist.js"></script>
```

Плагин спросит код мероприятия, обменяет его на временную сессию и отправит запрос `/v1/draw`. Для пилота в браузере на другом origin укажите `data-gateway="https://artist.example.org"` на том же теге. Для `file://` потребуется отдельно разрешить `null` origin и временные токены; по умолчанию этот режим для ИИ не включён. Сам редактор работает офлайн.

Из каталога `directive-ai` на ВМ запустите `docker compose -f deploy/compose.yaml up -d --build`, разместите reverse proxy с TLS перед `127.0.0.1:4242`, настройте `ALLOWED_ORIGINS` на адрес раздачи редактора. `/healthz` показывает состояние. Не храните `.env` в репозитории. Заморозьте содержимое `/artist/v1/artist.js` на время занятия.

Ограничения: сессии и счётчики хранятся в памяти одного процесса; после перезапуска коды нужно ввести заново. Cloud использует OpenAI-compatible Chat Completions JSON mode; поддержка конкретной модели зависит от её API. Настоящий провайдер и TLS не проверялись без ключа и ВМ. Нагрузочный пилот остаётся перед мероприятием.
